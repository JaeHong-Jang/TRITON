# 단계 계획

주제: **AI 법정** — 검사·변호 AI가 온톨로지로 분류한 근거로 다투고, 사람 판사가 1·2·3심에서 판결하며, 판사의 모든 개입이 신뢰도 장부에 남는다.
기능별 상태는 `progress.json`이 기준이고 앱의 「구현 현황」 화면에 그대로 보인다.

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| P0 하네스 | 폴더·계약·규칙·단일 서버·검증 스크립트 | `./run.sh`로 한 서버에서 화면과 API가 뜸, `verify.sh` 통과 |
| P1 온톨로지·스킬 | 근거 온톨로지와 에이전트 스킬 파일, 근거 입장(찬성/반대)·핵심어 부재 근거 | 모든 주장이 온톨로지 유형·입장을 갖고 코드 검증됨 |
| P2 백엔드 API | 사건·재판 기록·장부·작업 큐·정답 보호 | API 계약 전 엔드포인트 테스트 통과 |
| P3 법정 화면 | 찬성/반대 접시에 근거가 쌓이는 천칭, 지금 단계·다음 행동이 보이는 진행 UI | 브라우저에서 1심 끝까지 진행 |
| P4 2·3심 | 전문 분담 팀, 반대신문, 재판연구관, 합의부·다수결, 조치 단계 | 항소 → 2심 생성·판결 → 3심 최종 판결까지 진행 |
| P5 운영 화면 | 접수처(약식/회부), 기록실(판결문), 통계실 | 장부에서 다시 계산한 값과 화면 수치 일치 |
| P6 실험실 | 조건 A/B/C, 정답 공개, 레드팀 변형 | 세션 하나를 끝까지 진행하고 통계에 반영 |
| P7 검증 | 기능·UI 리뷰와 수정 | 리뷰 지적 해결, 전체 검증 통과 |
