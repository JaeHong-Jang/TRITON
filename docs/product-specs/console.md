# 운영 콘솔 계약

## 기사 직접 등록

사건 접수의 **새 기사 등록**에서 제목·본문과 선택 분야를 입력한다. 본문은 빈 줄을 제외한 줄마다 근거 번호가 붙는다. 등록 후 성공 안내와 **법정으로 이동**을 제공하고 목록 필터를 초기화해 새 사건을 표시한다. 빈 목록에서는 등록 버튼을 안내한다. 등록은 모델 연결 없이 가능하며 실제 변론에는 Ollama가 필요하다. 직접 등록 기사는 정답 비교 대상이 아니다. 모의 모드는 세션 저장과 기사 읽기·첫인상만 지원한다. 상세 계약: [registration.md](../contracts/registration.md).

앱 전체를 왼쪽 메뉴가 있는 운영 콘솔로 구성한다. 법정은 콘솔 안의 한 화면이다.

## 메뉴와 경로

| 묶음 | 메뉴 | 경로 | 내용 |
|---|---|---|---|
| | 대시보드 | `/` | 핵심 지표, 지금 작동 중인 에이전트, 최근 활동(장부 + 에이전트 이벤트), 바로 가기 |
| 재판 | 사건 접수 | `/cases` | 사건 목록, 약식 처리 / 재판 회부와 사유, 「재판 열기」 |
| | 법정 | `/court/:caseId` | 2D 법정, 판사 단계, 실시간 변론 |
| 에이전트 | 작업실 | `/agents` | 사무실 그림 위에 에이전트가 일하는 모습(방: 서기실 · 검사실 · 변호인실 · 재판연구관실 · 증거 검증실), 방마다 「업무 · 진행 · 확인」 수, 에이전트별 신뢰도 카드 |
| 규칙과 기록 | 규칙 · 온톨로지 | `/rules` | 온톨로지 그래프, 자율 범위 정책(약식 처리 기준 · 조치 단계), 스킬 버전 |
| | 감사 장부 | `/records/:caseId?` | 판결문, 사건별 근거 그래프, 장부 타임라인, 에이전트 작업 기록(trace) |
| | 통계 · 비용 | `/stats` | 신뢰도 통계 + 모델 호출 수 · 토큰 · 시간 |
| | 실험실 | `/lab` | 판사 판단 실험(조건 A/B/C), 레드팀 변형 |
| | 구현 현황 | `/progress` | 메뉴 맨 아래, 옅게 |

- 위 막대: 현재 메뉴 이름, 「AI 작동 중 n」 표시(작업이 있을 때), 판사 이름.
- 법정 화면 위에는 경로(「사건 접수 › 분야」)를 쓰지 않고 기사 제목만 쓴다.
- 런타임 3D 엔진은 사용하지 않는다. 법정은 3D 렌더 이미지와 CSS/SVG 모션으로 표현한다.

## 실행 그래프 표시

- 법정은 현재 사건 단계, 에이전트의 실제 노드, 다음 단계 조건과 판사가 해야 할 행동을 보여준다. 기술적 전이·이력은 펼쳐 본다.
- 작업실은 현재 노드와 대기/수정 상태를 표시한다. 첫인상 전에는 상세 오류와 주장 내용을 숨긴다.
- 감사 장부는 실행 ID·버전·시도와 실제 이벤트를 근거 그래프와 구분한다. 실행 이력이 없는 기존 기록은 그 사실을 표시한다.
- 규칙 화면은 호출·수정·재개 한도, 첫인상 공개 조건과 사람 판결 조건을 설명한다.
- 대시보드·통계의 정답 기반 정확도는 최종 확정 사건만 대상으로 한다. 표본이 없으면 미측정으로 표시한다.
- 신뢰도 지표는 비율과 함께 분모(표본 수)와 집계 범위(확정 사건 / 공개된 재판 기록)를 보이고, 그 수치로 어떤 운영 판단을 했는지 한 줄로 밝힌다 (예: 서기 정확도 기준 미달 → 약식 처리 끔). 분야별 재현율의 표본 부족 판단은 `screeningSample`로 한다.
- 첫 화면은 이 서비스가 푸는 문제(낚시성 기사: 제목이 본문과 다른 기사), 방법(AI 검사·변호가 근거로 다투고 코드가 인용을 원문과 대조, 판결은 사람), 근거(모든 판단을 장부에 남겨 AI를 어디까지 믿을 수 있는지 측정)를 먼저 보인다.
- 법정은 판사가 답할 질문(이 기사는 낚시성인가 — 제목이 본문 내용과 다른가. ‘예’가 찬성 쪽이 되도록 묻는다)을 위에 보이고, 장면 아래 공개된 근거 목록은 원래대로 기본으로 접어 개수만 보인다 (펼치면 근거 카드, 2026-10-10 사용자 결정으로 기본 펼침을 되돌림). 실행 그래프 버전·시도 번호·영문 단계 id 같은 기술 정보는 ‘자세히’ 안에 둔다.
- 찬성(낚시성이다)은 진한 붉은색, 반대(낚시성 아니다)는 진한 남색으로 나무·석재 테마와 맞춘다. 찬반 묶음 제목은 배경 띠 없이 글자색만 쓴다. 페이지 설명은 넓은 화면에서 한 줄로 쓴다.
- 판사 화면에는 내부 id(i2-E5, i1-C3)·조치 코드만(L1)·영문 단계 id를 그대로 쓰지 않는다. 근거는 ‘검사 1의 근거 · 15번 문장 인용’처럼, 조치는 ‘독자에게 안내’처럼 쓰고 코드는 설명(툴팁)이나 기록실에 둔다. 판사석 판결 버튼은 원래대로 ‘낚시성 (유죄) / 낚시성 아님 (무죄)’를 쓴다 (2026-10-10 사용자 결정으로 되돌림). 판결 사유는 글자 수 제한 없이 선택이며, 순위 하향·제재(L2·L3) 승인에만 사유가 필요하다. 재판연구관 보고서 확인은 보고서 카드 안에서 한다. 장면 아래 근거 카드는 ‘지금 일어나는 일’ 카드와 같은 흰 카드·얇은 테두리에 왼쪽 선만 찬반 색으로 쓴다.
- 법정의 ‘지금 일어나는 일’ 카드는 대시보드 진행 현황 카드와 같은 모양(흰 카드·얇은 테두리·왼쪽 황동색 선·작은 제목 줄)으로 쓴다.
- 판정이 필요한 근거가 있으면 남은 개수와 ‘첫 번째로 이동’을 안내하고 해당 근거를 강조한다. 판결 입력 영역은 사건 기록을 가리지 않는다.
- 지표의 상태색(기준 미달·양호)은 찬반 색과 겹치지 않게 호박색·녹색을 쓰고 글자로도 밝힌다. 표본이 기준보다 적은 비율은 모든 화면에서 같은 형식(‘표본 부족 · n건 중 k건’)으로 보인다. 모바일 판정 버튼은 손가락으로 누를 수 있는 크기(약 44px)로 둔다. 한국어는 단어 단위로 줄을 바꾼다.
- 실제 생성·저장 기록 재생·모의 시연을 구분한다. 모의 시연은 전체 화면에 식별 가능한 표시를 유지한다.

계약: [execution.md](../contracts/execution.md). 모델·데이터가 없으면 준비 상태와 실패 사유를 표시하고 성공을 연출하지 않는다.

## 석조 법정 공통 테마 (2026-10-03)

법정에서 승인한 석재·황동·아이보리 색감을 모든 메뉴에 적용한다. 사건 접수의 도시 사진, 대시보드 도시 파노라마, 작업실의 미래도시 배경과 유리 타워 표현은 제거한다. 기존 `stone-tribunal.png`는 배너와 작업실 배경에 재사용하고, 문서 영역은 밝고 단정한 바탕을 유지한다. 사이드바·상단·버튼·입력 포커스는 같은 테마를 사용한다.

작업실은 법정의 여섯 업무실과 연결 통로로 표현한다. 역할, 작업 상태, 지도 확대·선택과 법정 이동은 유지한다. 각 역할의 색상과 검증·오류·성공의 의미 색은 계속 구별한다. 법정의 저지맨·천칭 모션과 재판 절차는 유지한다.

기사 등록, 검색·필터, 첫인상·정답 공개 조건, 사람 판결 및 실제/모의 구분은 기존 계약을 따른다. 배경과 조명은 실제 작업 상태를 의미하지 않는다. 모바일 가로 넘침 방지, 키보드 포커스, reduced-motion과 자산 실패 시 조작 가능성을 유지한다. 이전 시각 방향은 [미래도시 기록](../design-docs/future-city-console.md)에 보존한다.

## 글꼴 (2026-10-03)

제목·본문·메뉴·버튼·입력창·법정과 작업실의 SVG 라벨은 Pretendard로 통일한다. Pretendard v1.3.9 가변 WOFF2와 라이선스를 앱 자산으로 포함하고, 로드 중에는 시스템 고딕을 표시한다. 명조체 제목은 사용하지 않는다.

## 그래프 관제 작업실 (2026-10-03)

`/agents?caseId=…&instance=…`는 사건과 심급을 선택하는 관제 화면이다. 기존 사무실 그림 대신 실행 제어, 병렬 준비/첫인상 합류 파이프라인, 근거·온톨로지·연결 보기, 선택 상세, 검증 셀, 실행 및 사람 장부를 제공한다. 밝은 공통 셸과 어두운 목재 그래프 캔버스, Pretendard를 사용한다.

실행 상태는 execution API, 기록은 records, 내부 절차는 workflow, 정적 개념은 ontology를 사용한다. 기록과 실행은 같은 사건/심급의 응답만 결합하며 전환 시 이전 상세/통계를 지운다. 첫인상 전에는 원문과 정적 온톨로지만 탐색 가능하고 AI 주장·관계·건수·검증 결과·호출/수정 통계는 숨긴다. 이벤트는 서버 공개 투영을 사용한다. 실행·수정은 기존 시작/취소/retry API를 사용하고 사람 입력은 법정으로 이동한다. 과거 심급/확정 사건에서는 생성 제어를 제공하지 않는다.

그래프의 '지지 근거로 제출'은 AI 주장이고 원문 검증 및 사람의 채택과 별도다. 문장 번호 오류는 제출 위치와 실제 발견 위치를 구분한다. 판결 기록에 명시적 근거 참조가 없으면 판결→근거 관계를 만들어 내지 않는다. 현재 온톨로지와 기록 버전이 다르면 연결 보기를 차단한다. 없는 개념은 미정의로 표시한다.

확대·축소·이동·전체/선택 중심·관계 라벨·군집 접기·필터·목록 보기를 지원한다. 선택과 새 데이터는 화면을 자동 이동시키지 않는다. 검증 셀과 로그 선택은 그래프 상세와 연결한다. 모의/저장 기록/실시간은 구분하고 모델이 없으면 시작을 차단해 사유를 안내한다.

## 옵시디언식 관계 그래프 (2026-10-03)

관제의 관계 캔버스는 작은 원형 노드, 얇은 연결선, 어두운 단색 바탕과 절제된 제목 라벨로 표현한다. 격자·고정 역할 구역·큰 카드 도형·군집 타원은 제거한다. 실제 관계를 인력으로 사용하는 결정적 force 배치로 연결된 항목이 자연스럽게 모인다. 연결 수에 따라 노드 크기를 조금 달리하고 역할 색을 사용한다. 공개 데이터가 적으면 실제 수만 표시한다.

노드 선택/호버 시 인접 관계를 강조하고 나머지는 흐리게 한다. 노드 드래그, 빈 공간 이동, 휠/버튼 확대, 맞춤과 전체 화면을 지원한다. 복잡한 필터는 펼쳐 사용하고 키보드/목록 탐색과 상세 원문 연결을 유지한다. 배치 계산은 유한 횟수로 끝나며 동일 데이터 갱신은 기존 좌표와 시점을 흔들지 않는다. 첫인상·정답 공개와 사람 판결 계약은 그대로 적용한다.
