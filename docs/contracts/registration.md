# 직접 기사 등록 계약

`POST /api/cases`는 `{requestId, title, body, category?}`를 받아 공개 `Case`를 반환한다(201, 동일 요청 재전송도 201). 모델 호출 없이 저장한다.

- requestId: UUID 문자열. 같은 ID와 정규화된 내용은 같은 사건, 같은 ID에 다른 내용은 409. 서버 재시작 후에도 유지한다.
- title: 앞뒤 공백 제거 후 1~300자. body: 원래 입력 최대 20,000자, 비어 있지 않은 줄 1~300개. category: 앞뒤 공백 제거 후 1~40자, 생략 시 `직접 등록`.
- 본문은 CRLF/CR을 LF로 통일하고, 각 줄의 앞뒤 공백과 빈 줄만 제거한다. 남은 줄에 1부터 근거 번호를 붙인다. 문장 의미를 재작성하거나 명령문을 실행하지 않는다. 한 줄에 여러 문장이 있으면 한 근거 단위다.
- 허용하지 않은 필드(정답, 문장 번호, 사건 ID 등)와 부적절한 타입은 422. 입력 오류는 저장하지 않는다.
- 서버 생성 `manual-<uuid>` ID, `origin: 'manual'`, `subcategory: '사용자 입력'`, 빈 subtitle, variantOf/attack null. `Case`와 `CaseSummary`의 origin은 선택 필드(`'manual' | null`)이며 이전 사건과 호환한다.
- 원자적으로 `data/cases/manual.jsonl`에 저장한다. 기존 cases.jsonl과 함께 조회한다. 데이터셋 재변환이 직접 등록 사건을 덮어쓰지 않는다. 등록 requestId 등 내부 메타데이터는 공개 API와 프롬프트에 제외한다.
- 직접 등록 기사에는 정답을 만들지 않는다. 정답 API의 확정 전 403, 확정 후 정답 없음 404 계약을 유지한다. 최종 화면은 직접 등록 기사에 정답/정확도 비교가 없음을 중립적으로 표시한다. 정답 없는 사건은 실험실 A/B/C 정확도 표본에서 제외한다.

## 화면과 실행

사건 접수의 `새 기사 등록` → 제목·본문(필수), 분야(선택) 입력 → `기사 등록` → 성공 안내와 `법정으로 이동`. 입력 실패 시 내용을 유지하며 한국어 사유 표시. 같은 제출의 재시도에는 같은 requestId를 사용하고 내용을 바꾸면 새 ID를 사용한다. 제출 중 중복 클릭을 차단한다.

AI 작성 여부와 무관하게 제목·본문을 입력할 수 있다. 실제 AI 변론은 법정에서 별도로 시작하며 Ollama 모델이 필요하다. 새 기사는 첫인상 전 AI 의견 비공개 규칙을 그대로 적용한다.

첫인상 기록은 AI 변론 파일이 없어도 저장·재생할 수 있어야 한다. 모델 실패 후 새로고침해도 기록한 첫인상은 유지하고, 변론·판결은 필요한 재판 기록이 생길 때까지 대기한다.

모의 모드는 같은 등록 UI와 세션 저장을 제공한다. 직접 등록 기사의 원문 조회·첫인상 실험까지만 지원하고 AI 변론 생성은 명확한 안내로 차단한다. 기존 예시 기사의 모의 변론과 섞지 않는다. 실제 기사 분석은 실제 서버에서 시작한다.
