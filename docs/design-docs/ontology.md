# 근거 온톨로지 설계

정의 파일: `agents/ontology.yaml` (프롬프트·스키마·검증·통계·그래프가 모두 이 파일을 읽는다).

| 개념 | 값 | 설계 이유 |
|---|---|---|
| 입장(stance) | 찬성(낚시성이다, 왼쪽 접시) · 반대(낚시성 아니다, 오른쪽 접시) | 천칭의 어느 접시에 쌓일지를 에이전트가 아니라 온톨로지가 정한다 |
| 주장 유형 | 찬성 4 (제목-본문 불일치, 무관한 내용 삽입, 과장·선정적 제목, 핵심 정보 은닉·호기심 유발) · 반대 3 (제목이 본문 핵심을 반영, 본문 주제 일관, 표현은 강하나 사실과 일치) · 반박(입장은 대상 근거의 반대) | 에이전트는 유형만 고르고 입장은 유형에서 자동 결정 → 같은 모델이 양쪽을 맡아도 구조가 무너지지 않음 |
| 근거 종류 | 본문 인용(문장 번호 + 글자 그대로) · 핵심어 부재(제목에는 있고 본문에는 없음) | 둘 다 코드로 검증 가능한 형태만 허용 |
| 검증 상태 | 원문 확인 · 문장 번호 오류 · 제목 인용(증거 아님) · 핵심어가 본문에 있음 · 위증 의심 | 상태마다 무게 배수가 정해져 있고 위증은 주장 전체를 무효로 만든다 |
| 관계 | 뒷받침 · 반박(상대 근거 하나를 겨냥, 검증되면 대상 무게 절반) | 2심 반대신문을 천칭에 반영 |
| 조치 단계 | L0 조치 없음 · L1 독자 안내 (AI 자율) · L2 노출 하향 (사람 승인) · L3 언론사 통보 (사람만) | 되돌리기 쉬울수록 AI 자율 범위 |

바뀐 이력과 이유는 `docs/experiments/findings.md` (예: 제목 인용 상태 추가, 부재 후보를 코드가 계산, 입장을 스키마로 강제).
